Six read-only Opus 5 auditors, one per domain (grading core, HTTP/config, client, engram, the MCP contract, pipeline + build), orchestrated and spot-checked by Fable 5. Nothing was edited. Both repos at working-tree HEAD: myelin 7a6ad6b plus the uncommitted FirstRun diff, engram 1e229e6.

I re-verified the four claims below marked checked by reading the code myself; the rest are the auditors' with their stated confidence.

Critical

No auth, CORS or origin middleware exists. gap/service.ts:343 runs body.code for node/python3/bash/ruby/c/rust directly on the host (only go/java get the hardened docker tier). Anyone on the same Wi-Fi gets code execution as you, plus the vault and ~/.config/myelin/credentials.json. Same door: POST /api/ingest {path} reads any local file into raw/uploads/ and /api/source serves it back (ingestRoutes.ts:53, restRoutes.ts:486). Fix: serve({ fetch, port, hostname: '127.0.0.1' }). Electron already probes 127.0.0.1.

C2 code_exercise grades 0/0 tests as applied-correctly. checked grading.ts:827 suiteGreen = testsPassed === testsTotal is true for 0 === 0. The client's "tests aren't passing, submit anyway?" path sends testsTotal: 0 (CodeExercise.tsx:288-301). High

H1 isTransportError matches ordinary vault errors and leaks an engram process each time. checked mcp.ts:11 /closed|EPIPE|transport|disconnected/i is run against engram read_page: page not found: closed-loop-control. A routine miss on any slug containing those words respawns engram and overwrites this.client without closing the old child (mcp.ts:83). Unbounded process growth on a control-theory or networking vault. Fix: match only the stdio client's own message shape, and close() before respawn.

H2 Concurrent page writes lose updates; engram has no serialization. Both auditors converged. engram write_page/link_pages do await snapshot() → compute → write (graphTools.ts:133,164,194), a real yield point. myelin's parallel allowlist only governs fan-out within one model step; compile runs 4+ write_page workers concurrently (ingest.ts:785,956), and the Anki cron's record_evidence races live chat turns on one student file (index.ts:122, teachTools.ts:147). A MOC link_pages landing mid-compile reverts the body just written; both return success. Fix: a per-slug (or global) write mutex inside engram, so the guarantee stops living in the client.

H3 Engram misconception dedupe destroys distinct entries. Auditor ran the real function. model.ts:154-169 treats substring containment as "same": ['off by one', 'off by one in the loop bound'] heals to ['off by one'] on any unrelated write; recording 'sign error when integrating by parts' over an existing 'sign error' is dropped. Both from the two newest engram commits; tests cover only identical and disjoint strings. Also resolves: '' (schema has no .min(1)) matches index 0 and deletes an arbitrary misconception while logging a false repair (model.ts:143).

H4 Every engram page write strips unknown frontmatter. parsePage.ts:78-105 keeps eight fields; writePage overwrites the file. Obsidian aliases, cssclasses, Dataview fields on a page vanish on the next link_pages. The round-trip fuzz test compares already-stripped meta so cannot see it.

H5 A turn that fails after grading loses the evidence silently. session.ts:885-1215 grades, streams the grade to the client, then calls the model; record_evidence and the guardrail run only on success. Provider 5xx or the stop button after grading: card shows green, mastery never moves, guardrail.log empty, and pendingBlockOutputs never re-grades because output.grading is set. Same shape in rails.ts:516-531: grader not wrapped, record_evidence result never inspected.

H6 numeric checker unit match is a substring. grading.ts:330,364 unitKey('20 km/s').includes('m/s') → correct. g/kg, m/mm, s/ms all pass. The unit checker kind does this properly through mathjs; route numeric-with-unit through it.

H7 openai: tutor silently loses web search. webTools.ts:21 isAnthropicRouted = "not ollama:", but models.ts has three routes. An openai: model is handed the Anthropic web_search server tool, which openaiCompat.ts:158 drops; SearXNG branch is unreachable; hasWebSearch in the prompt still says true. setupRoutes.ts:97 handles all three, so this is a missed mirror.

H8 Anki two-way sync is one-way in production. checked syncOutbound has zero callers outside its test. Nothing ever writes anki-map.json, so syncInbound early-returns on every tick forever. Status badge says "anki: up". When it is wired, both modules read-modify-write the same ledger across long awaits (inbound.ts:66-128, outbound.ts:104-177) and readLedger in both is an unguarded JSON.parse, which turns /api/status into a 500 on a torn file.

H9 No store write in either repo is atomic. Thirteen writeFileSync sites in myelin (queueStore, goalStore, stanceStore, sessionStore, courseBank, provenance, scheduler, anki, linkList, gap/generated) and engram's writePage/appendReviewLog/saveRationale (atomicWrite exists at vaultStore.ts:44, used only for students). Graceful reads make this worse: a torn compile-queue.json reads as [] and the next updateQueue writes [] back as truth. One tmp+rename helper covers all of it.

H10 Uncommitted FirstRun diff regresses the model-prefix rule. FirstRun.tsx:119 now reveals the OpenAI-compatible fields for any non-ollama: id, but a bare id is the Anthropic route. Typing deepseek/deepseek-chat, filling base URL + key, and pressing Use it saves, re-reads, stays blocked: true, and renders the same card with no message (FirstRun.tsx:92-97 only errors on !res.ok). The new test at firstRun.test.tsx:118 pins this behaviour, and stubFetch returns blocked: false by call count regardless of what was PUT, so no test in the file can see the dead end. Do not commit as is.
